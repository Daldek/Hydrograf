# ADR-071: PGW ownership with cell-level boundary-event routing, not cycle merging

**Date:** 2026-11-06 (measured 2026-11-07)
**Status:** accepted (design; implementation pending)

## Context

Hydroni needs the entire 2,940.7 km² area at 5 m without loading roughly 117.6 M DEM cells into one process. F1–F7 reduce per-cell memory but do not make one full-area raster safe alongside production. The Nogat Hydroni plan `docs/plans/2026-11-06-hydroni-instance.md`, D3, delegates processing by PGW units and initially proposes merging cyclic unit graphs. The approved, measured Hydrograf implementation plan is `docs/plans/2026-11-06-processing-by-units.md`.

A 20 m bilinear mosaic of all 708 NMT sheets, using this branch's real depression fill, D8, sink fix and accumulation without stream burning, has 26 river JCWP owners plus one `LW10235` remainder, covering every area cell. It contains **25,079 D8 crossings on 123 ordered unit pairs**: 24,962 cross with <1 km² upstream (hillslope scale), 24 with ≥10 km² upstream within 250 m of the receiving JCWP river line (conservative main-river proxy), and 93 intermediate or unmapped high-area crossings. Their summed source areas are 114.82, 7,533.16 and 727.61 km² respectively; these are **not disjoint contributing areas** when a river crosses boundaries repeatedly. All **27** PGW units belong to one strongly connected component of the raw unit graph; edges ≥1 km² still make SCCs of 11 and 9 units, and edges ≥10 km² leave five small cycles. A same-window 20 m/5 m check of one pair changes the largest directed transfer from 18.864 to 20.052 km² (+6.3%); a nearby reverse edge drops from 102.48 to 0.38 km². Full details and the limits of this coarse-resolution proxy are in the plan.

The unit graph is a quotient of **directed cells**, not a river topology: several crossings may run in opposite directions between two polygons while no D8 cell drains back to itself. A unit topological sort does not exist, and merging all SCCs destroys the memory bound.

## Alternatives

- Merge every unit-graph cycle (original D3 proposal): **rejected**; here it collapses 27 owners into the whole area.
- Ignore hillslope crossings or merge only pairs over an area threshold: **rejected**; 24,962 small crossings still contribute, and a 20 m threshold can misclassify even 100 km² transfers at 5 m.
- Relabel every leaking hillslope or winding main-river path to its receiving PGW unit: **rejected as a default**; ownership then depends on iterative DEM divides, can swallow large areas and does not bound the next cycle or the rectangular raster footprint.
- Preserve PGW owner polygons; route the D8 boundary **events**, which form a DAG whenever the global D8 is acyclic: **chosen**. This keeps the PGW map intelligible, memory bounded by a local window, and exactly accounts for every crossing without conflating the unit graph with the flow graph.

## Decision

`--units FILE` opt-in to the bootstrap accepts the PGW GeoPackage. Use the 26 river JCWP catchments clipped to `obszar` plus `LW10235` as one separate owner; direct lake catchments already overlap river owners and do not make new units. Rasterize owners without gaps on a snapped EPSG:2180 5 m grid. For each unit use a **500 m DEM halo** for burning, filling and D8, including exterior contributing fringe where needed. Halo cells never become owned raster/DB outputs. Verify consistency in overlaps, propagate spill/flat boundary conditions and refuse an unresolved seam; 500 m by itself does not guarantee identical whole-area fill/D8. Preserve genuine drain points and the single-raster sink rules. Process one owner at a time; if a larger depression or bbox breaks the 4 GB worker budget, spill boundary summaries to disk or split owned work, never merge cyclic units into an unbounded region.

Store D8 boundary events with exact `(source owner, source cell, receiving owner, receiving cell)` identities. Form local D8 transfer summaries; topologically route these **events** upstream→downstream, injecting the complete outflow accumulation into the **receiving cell** (once), then adding that cell's own contribution and routing onward. A river can revisit a PGW unit without making a cell-level cycle. Persist local cores and reopen them for the second/finalization phase: globally corrected accumulation drives stream thresholds, Strahler order and upstream path heads; downstream→upstream propagation supplies the true flow distance to the final outlet, downstream segment identity and every catchment label. Count the seam D8 step once. A seam is a segment boundary even without a confluence, and a single upstream continuation must not inflate Strahler order. No local-only accumulation, flow path, order, label or catchment polygon may be presented as global. Dissolve owned geometry fragments by global catchment id where they straddle a unit edge.

Allocate **1-based, dense global `segment_idx` per threshold** by deterministic unit order and prefix-sum offsets of local segment counts. Remap stream rows, catchment rows, label rasters and cross-unit `downstream_segment_idx` after counts are final; multiple upstream segments keep their own downstream links. Preserve the existing `(threshold_m2, segment_idx)` `CatchmentGraph` lookup and CSR traversal; no API compatibility alias or separate unit-scoped graph id. Add `processing_runs` and `processing_units` tables to record immutable input fingerprints, grid/config, unit phase, output checksums and per-threshold counts/offsets. Write per-unit results to run-scoped staged DB rows and owned-cell raster files with an idempotent transactional unit checkpoint. Restart reuses only units whose stored inputs/outputs still match; stale or partial outputs are recomputed. The published tables, rasters and tiles stay from the preceding complete run until validation succeeds and a single publication transaction activates all new rows and the associated raster/tiles manifest. Do not clear shared tables once per unit.

Write each raster type as nonoverlapping, one-grid owned-cell tiles (including filled DEM, D8, accumulation, flow distance, stream order and labels); expose whole-area VRT mosaics that contain **no buffer overlap** or holes. Generate existing MVT streams/catchments from the completed global DB network and DEM tiles from the whole-area DEM VRT; publish tiles with the run. Runtime D4 must window-read the VRT before deploying the whole area. The **default without `--units` remains the existing single-VRT run** (same equations, output names and API). PGW routing changes only the opt-in preprocessing and adds no API mode.

## Consequences and verification

The 500 m buffered largest owner has about **33.8 M cells**; the F1–F7 estimate is **1.69 GB decimal of arrays at 50 B/cell**, plus allocator/I/O overhead. Measure and cap one worker at **4 GB** on the production host; an event queue/streaming unit reread is preferable to merging or loading the full 117.6 M-cell area. Actual D8 seams and the peak RSS remain acceptance conditions, not assumptions inferred from the 20 m experiment.

Synthetic two-/three-unit DEMs must agree with an uncut single-raster reference on filled DEM, D8, accumulation, outlet flow distance, threshold-specific stream masks and Strahler order, subcatchment labels/geometry/areas and all downstream graph links, modulo deterministic segment-id renumbering. Cases include unit-graph cycles with acyclic cells, hillslope crossings, confluences at boundaries, spill basins beyond the halo, exterior inflows and restart after a per-unit commit. Check published DB/VRT/tiles as one run; never promote a run with a missing unit, seam mismatch or unresolved cell-level cycle.
